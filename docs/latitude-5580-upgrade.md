# Dell Latitude 5580 — план апгрейда

Дата фиксации: сентябрь 2026. Куратор апгрейда — сам, Claude — консультант.
Цель: из i7-U + 930MX сделать рабочий терминал-разработчика; через год — на замену, себе собрать новое.

## Исходное состояние
- Dell Latitude 5580, i7 U-серии (Kaby Lake), NVIDIA 930MX
- RAM: 32 ГБ, одна планка Samsung **M471A4G43AB1-CWE** (DDR4-2400 SO-DIMM, non-ECC)
- NVMe 1 ТБ
- WWAN-антенны в крышке уже есть, SIM-слот физический (не заглушка)
- Родное питание — Dell 7.4 mm barrel; USB-C только DisplayPort, без зарядки

## Решения, принятые в обсуждении
- Процессор не апгрейдится дальше E3-1505M v6 — это потолок платформы; для QEMU/nix-сборок/агентов **тяжёлое уезжает на m90q**, ноут — редактор, ssh, браузер, dwl.
- 64 ГБ в ноуте не нужно при наличии m90q как remote builder.
- Xeon + Thunderbolt оправданы: TB даёт док и eGPU (TH3P4G3 + RTX 3090 24 ГБ — рабочий сценарий, упирается в PCIe x4 Gen3, ~10–20% потерь).
- **Бюджетная альтернатива 3090 — CMP 50HX → 20 ГБ (compute-only), ~250 CHF с чипами.** См. раздел ниже.
- Альтернативы (ThinkPad P16 Gen2, Precision 3591, Framework 16) — отложены; текущий 5580 добиваем до максимума и передаём дальше.

## eGPU: CMP 50HX 20GB под llama.cpp (проект, ноябрь 2026)
Цель двойная: дешёвая 20 ГБ CUDA-карта для локальных LLM + навык ремонта видеокарт.

**Карта:** MSI CMP 50HX — TU102 (как 2080 Ti), 3584 CUDA, 10 ГБ GDDR6, 320-бит (10 чипов), 250 Вт, 2×8-pin, 268×114×36 мм. Без видеовыходов, без NVENC, сток — PCIe 1.1 x4 (~1 ГБ/с).

**Мод памяти → 20 ГБ (не 22: 10 посадочных мест, не 11):**
- Чипы: 10× Samsung **K4ZAF325BM-HC14** (16Gb, 14 Gbps) или Micron D9ZCL. BGA-180, шаг 0.75 мм.
- Мод отработан сообществом: репо **github.com/xrip/cmp50hx-unlock** (патч драйвера 610.43.03: полные SM + тензорные ядра, PCIe Gen2, ReBAR, поддержка 20GB — FWSEC/WPR2 обработан), видео «Upgrading CMP 50HX to 20GB and PCIe x16 | Full Guide», Kiya GraFix «[MOD4]» (Discord с диагностикой).
- Заодно можно распаять PCIe x16 (дорожки есть, компоненты не распаяны) — **через TB бесполезно**, TB всё равно x4. Ограничиться патчем Gen2.
- Известный провал (badcaps.net, 03-2026): после перепайки карта не инициализируется, нет доступного MATS/NVMT под TU102 для теста банков. Главный риск — кривая посадка одного из 10 чипов, а не VBIOS. Без видеовыхода диагностика только по `nvidia-smi`/CUDA-ошибкам.

**Порядок:**
1. Карта → стоковый патч xrip на NixOS → `llama-bench` на 10 ГБ, зафиксировать базу. Учёба ИИ не останавливается.
2. Тренировка пайки GDDR6 на убитой донор-плате.
3. Перепайка → `nvidia-smi` (20 ГБ?) → `cuda-memtest`/`gpu-burn` → `llama-bench` на 32B Q4 (заполнение верхних адресов ловит битые чипы).

**Док:** TH3P4G3 (Titan Ridge JHL7440, открытая плата, ATX БП ≥550 Вт, 24-pin + 2×8-pin). Длина/2 слота — не проблема. Кабель — сертифицированный TB3 40 Гбит, без магнитных переходников.

**Хост-сторона (плата 3520, JHL6540 Alpine Ridge):** ~2.2–2.7 ГБ/с реально — карта в сток/Gen2 в док не упрётся. На стоковом Dell BIOS: Thunderbolt Security = No Security (или `boltctl`). **ReBAR из патча xrip через TB не включать** — MMIO-окно за hotplug-мостом может не выделиться, для llama.cpp разница минимальна.

**NixOS:** упаковать патченный драйвер — `hardware.nvidia.package` с оверрайдом на 610.43.03 + патчи модулей из репо xrip. Графики нет → PRIME/offload не нужны, только `nvidia-smi` + llama.cpp. Сборка llama.cpp: `-DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=75`; запуск `-fa on -ctk q8_0 -ctv q8_0 -ngl 99`.

**Ожидания (уровень 2080 Ti):** 7–8B Q8 ~60–70 tok/s; 14B Q8 ~35–45; 27–32B Q4_K_M ~20–25 целиком в VRAM (контекст 8–16k с q8 KV); 70B — только с оффлоадом, 3–5 tok/s. Две 50HX 20GB = 40 ГБ за ~500 CHF → 70B Q4. Turing sm_75: нет bf16/FP8, llama.cpp — без оговорок, vLLM — с оговорками.

## Coreboot на 5580 — проект после апгрейда
Порта нет ни в coreboot, ни в Libreboot. Делаем сами, на **старой плате i7-U** как жертвенной.
- Фаза 0 (разведка, 1–2 нед): CH341A + клипса, дамп SPI (проверить, 1 или 2 чипа), `ifdtool`, `me_cleaner -c`, `inteltool -a`, `acpidump` → DSDT (EC-транзакции), **Boot Guard fused? (`intelmetool -b`, MSR 0x13A)** — если verified boot, проект закрыт.
- Фаза 1: скелет из `mainboard/dell/optiplex_3050`, GPIO через `intelp2m`, FSP Kaby Lake, payload edk2 → NixOS с внешней клавиатурой/монитором. Toolchain и флеш через Nix.
- Фаза 2: EC (база `ec/dell/mec5035`): клавиатура, батарея, кулер, крышка. Самый длинный этап.
- Фаза 3: eDP, яркость, S3/S0ix, Thunderbolt, SD, WWAN. Гибридная графика — вероятно, долго только iGPU.
  - TB/eGPU: JHL6540 — дискретный Alpine Ridge со своей NVM, для coreboot это обычный PCIe-девайс за root-портом PCH (референсы: ThinkPad T480, Purism). Проверить резервирование ресурсов под hotplug (bus numbers, MMIO выше 4G) — иначе eGPU только при холодном подключении. Обход на стороне ядра: `pci=realloc,hpmemsize=...,hpbussize=...`. **До прошивки снять со стока `lspci -tv` + `dmesg | grep -iE "pci|thunderbolt"` с подключённой eGPU** как референс распределения ресурсов.
- Фаза 4: апстрим в Gerrit coreboot.
- Промежуточный результат «здесь и сейчас»: me_cleaner + свои SB-ключи на стоковом BIOS.
